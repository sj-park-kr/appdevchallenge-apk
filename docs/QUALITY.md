# 완성도 개선 기록

## 조사 범위와 우선순위

차량 신호 처리부터 저장소·설정·앨범·공유 화면까지 코드를 살펴보고 기존 테스트를 실행했다.
이번 변경은 실제 사용자가 선택한 공개 범위가 지켜지는지, 공유 안내가 실제 동작과 일치하는지에 집중했다.

| 확인한 문제 | 반영한 변경 | 검증 |
|---|---|---|
| 이름 숨김 상태에서도 추억 제목에 동승자 이름이 남음 | 카드 미리보기와 QR이 같은 제목 처리 사용 | ShareTest, ShareScreenTest |
| 위치 수집 동의가 곧 공유 동의로 적용됨 | 공유 화면에 별도의 ‘장소 넣기’ 추가, 기본 꺼짐 | ShareScreenTest |
| 긴 장소·이름을 넣으면 제목만 줄여도 QR 300바이트 초과 | 모든 가변 항목을 UTF-8 바이트 기준으로 제한, 이모지 코드 포인트 보존 | ShareTest |
| QR에 이미지가 없는데 카드 저장으로 안내 | 글자 읽기와 화면 촬영 안내로 수정 | 기존 화면 캡처 테스트 |
| 동승자 삭제 후 앨범의 COMPANION 기억·현재 선택에 이름이 남음 | 세션에서 이름 목록·과거 기록·미확정 주행·현재 선택을 함께 변경, 과거 기억은 ‘친구’로 표시 | PassengerPrivacyTest |
| README가 이전 운행기록부 기획이고 SETUP은 임시 화면으로 안내 | 실제 펫 앱 기능과 실행·검증 방법으로 갱신 | 코드와 문서 대조 |

## 검증 방법

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug '-Proborazzi.test.record=true'
```

- 기존 도메인·저장소·플랫폼 테스트와 신규 회귀 테스트를 함께 실행한다.
- ShareScreenTest는 실제 Compose 화면의 스위치를 눌러 공개 범위와 제목 변경을 확인한다.
- ScreensTest는 세로·가로·차량 크기와 밝은/어두운 테마의 화면을 렌더링한다.
- 자동 생성 보고서와 화면 캡처는 빌드 산출물이므로 저장소에 추가하지 않는다.

1차 개선 검증 결과:

- Debug 테스트 182개 통과(신규 회귀 테스트 7개 포함).
- Release 테스트 179개 통과. Compose 화면 테스트 3개는 debug 전용 테스트 manifest를 사용하므로 Release 대상에서 제외한다.
- `assembleDebug`, `lintDebug` 성공.
- Pleos Connect Android 14 에뮬레이터에 `installDebug`로 설치 성공.
- 예시 상태의 공유 화면을 실제 Activity로 실행(`Status: ok`)하고 캡처를 확인했다. 이름·장소 기본 꺼짐, 숨긴 제목, QR과 안내가 정상 표시되며 AndroidRuntime 오류 로그가 없었다.
- 에뮬레이터 실행 확인은 공유 화면에 대한 시험이다. 실제 차량 신호에 대한 장시간 검증을 대신하지 않는다.

## 추가 개선: 저장 실패 대응과 장소 삭제

- 저장 실패 시 변경 표시를 유지한다. 정차 화면에 저장 실패와 수동 재시도 버튼을 표시하며, 자동 재시도는 30초 간격으로 제한한다. 재시도에서는 실패 당시 상태 대신 최신 상태를 저장한다.
- 저장 성공 시 안내를 닫는다. 주행 중에는 실패 안내·재시도 버튼도 숨긴다. 실패한 변경은 메모리에 있으므로 저장 성공 전에 앱을 종료하면 최신 변경을 잃을 수 있다.
- 설정의 ‘장소 정보 모두 지우기’는 확인 후 위치 사용을 끄고 장소 도장, 주행 기록의 장소, 장소 앨범 항목, 지역명이 남은 보상 키, 미확정 주행·체크포인트·감지기·내비 캐시의 장소를 지운다. 펫 성장과 일반 추억은 유지한다.
- 삭제 후 늦게 도착한 내비 콜백이나 이미 대기 중인 차량 샘플로 장소가 다시 저장되지 않도록 차단한다.
- 권한 거부·속도 신호 누락을 실제 속도 0과 구분한다. 신호가 없는 것만으로 에뮬레이터용 급제동·급회전 규칙을 적용하지 않는다. 기존의 ‘60초간 속도 0이면 에뮬레이터’ 검증은 명시적 `0.0` 입력으로 유지한다.

추가한 회귀 테스트 16개:

| 테스트 | 확인 내용 |
|---|---|
| SessionSaverTest (4개) | 실제 파일 쓰기 실패와 복구, 자동 재시도 대기, 수동 재시도, 최신 상태 저장, 변경 없는 상태의 불필요한 쓰기 방지 |
| PlacePrivacyTest (3개) | 장소 전체 삭제, 암호화 저장·재로딩 후 유지, 늦은 샘플로 재유입 방지, 짧은 주행의 위치 저장 차단 |
| VehicleRecoveryTest (4개) | 속도 권한 거부·신호 누락·복구, 체크포인트 재시작의 중복 기록 방지, 짧은 P↔D 전환과 시동 종료 |
| ScreensTestReliability (5개) | 권한 허용·거부, 실제 신호 소스의 내비 캐시 삭제, 저장 실패·재시도 UI, 주행 중 화면 숨김, 장소 삭제 확인 |

최종 검증: `test assembleDebug lintDebug '-Proborazzi.test.record=true'` 성공. Debug 198개, Release 190개 테스트가 모두 통과했고 APK 빌드·Lint도 성공했다. Compose 화면 테스트는 debug 전용 manifest 때문에 Release에서 제외한다.

## 남은 실제 기기 검증

Robolectric의 권한 상태·Compose 조작과 순수 세션 테스트로 위 예외 경로를 확인했다. 실제 차량에서 OS 권한 창을 조작하거나 물리적으로 신호 연결을 끊는 장시간 시험은 별도로 필요하다.

남은 구현 검토와 기기 검증의 구체적인 순서·관련 코드·완료 기준은 [HANDOFF.md](HANDOFF.md)에 정리했다.
