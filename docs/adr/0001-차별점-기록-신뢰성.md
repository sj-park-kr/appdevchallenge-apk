# 0001. 차별점은 "기록 신뢰성"으로 한다

- 상태: 채택 · 날짜: 2026-10-23

## 맥락
운행일지 자동화는 이미 상품화되어 있다(폰 앱, 통신사 단말기). 처음 구상은 "법인 차량 건강 기록부"로 인수인계 분쟁·차량 상태·잔존가치까지 묶었지만, 조사해 보니 근거 강도가 달랐다.
- 강함: 운행일지가 빠지거나 거짓이 된다는 공공기관 감사 지적(46% 누락, 목적지 '0', 경유차 휘발유 주유 기록)
- 약함: 운전 습관 → 부품 수명 → 잔존가치(독립 연구 없음), 공용차 인수인계 갈등(국내 자료 없음)

감사가 지적하는 칸(목적지·주행거리·주유)은 차량 데이터로 그대로 채워지는 칸이다.

## 결정
차별점의 중심을 **"차가 직접 써서 사람이 고칠 수 없는 기록"**에 둔다. 차량 상태·잔존가치 리포트는 로드맵으로 미룬다.

## 결과
- 모든 설계가 "자동값은 못 고친다, 고친 건 다 보인다, 빠진 것도 보인다"를 따른다([0008](0008-append-only-이벤트와-수정-이력.md), [0011](0011-운행-경계-시동-기준.md)).
- 기능 수가 줄어 MVP 범위가 마감(11/15)에 맞는다.
- 경쟁 서비스와의 차이를 "계기판 거리 + 순정 내비 목적지 + 변조·누락 탐지"로 설명해야 한다. 단순 자동화만으로는 차별이 안 된다.
