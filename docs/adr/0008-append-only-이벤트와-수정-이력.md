# 0008. 기록은 추가만 되는 이벤트 + 해시 체인으로 저장하고, 수정도 이벤트로 남긴다

- 상태: 채택 · 날짜: 2026-10-23

## 맥락
"사람이 고칠 수 없는 기록"이 차별점이다([0001](0001-차별점-기록-신뢰성.md)). 하지만 운전자·용무는 사람이 잘못 고를 수 있어 고칠 길은 필요하다. 운행 행을 UPDATE하는 방식은 원래 값이 사라지고, 별도 이력 테이블은 빠뜨리기 쉽다.

## 결정
- **이벤트 테이블 하나**에 모든 사실을 추가만 한다(운행 시작·체크포인트·도착·종료·공백·주유·운전자 선택·용무 선택·수정·직원·설정).
- SQLite 트리거로 `UPDATE`·`DELETE`를 거부한다.
- 각 이벤트에 `prev_hash`·`hash`(SHA-256)를 넣어 **해시 체인**을 만든다. 앱 시작·내보내기 때 검증하고, 엑셀에 마지막 해시를 찍는다.
- 자동값 칸(시각·계기판 거리·위치)에는 수정 이벤트를 받지 않는다. 사람 입력 칸과 목적지명은 `FIELD_EDIT`(사유 필수)로만 바꾼다.
- 운행 목록은 이벤트에서 매번 계산한다(별도 투영 테이블 없음).

## 결과
- 원래 자동값·이전 값·새 값이 항상 남아 "수정됨"과 수정 이력 시트를 쉽게 만든다.
- 직원·설정 변경도 누가 언제 했는지 남는다.
- **한계**: 루팅된 기기에서 DB를 통째로 다시 만들면 탐지 못 한다. 이미 내보낸 파일의 해시와 비교하면 그 이후 변조는 드러난다. Keystore 서명·서버 해시 보관은 로드맵.
- 이벤트가 매우 많아지면 계산이 느려질 수 있다 → 그때 투영 테이블을 추가한다(가정: 5년 안에는 불필요).
