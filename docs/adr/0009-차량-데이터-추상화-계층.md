# 0009. 차량 신호는 VehicleSource 하나로 가두고, AAOS 신호 의존을 위험으로 관리한다

- 상태: 채택 · 날짜: 2026-10-23

## 맥락
- 계기판 거리·연료·VIN은 Pleos Vehicle State, 위치·목적지·즐겨찾기는 NaviHelper로 읽는다.
- **시동·기어·속도는 Pleos SDK에 없다.** AAOS 표준 `CarPropertyManager`(`IGNITION_STATE`, `GEAR_SELECTION`, `PERF_VEHICLE_SPEED`)로 읽어야 하는데, Pleos 에뮬레이터·실차에서 서드파티 앱 권한으로 읽히는지 **확인하지 못했다.**
- PT는 에뮬레이터 실동작 시연이 필수라, 시연 때 신호를 원하는 순서로 넣을 수 있어야 한다.

## 결정
- 모든 차량 신호를 `VehicleSource` 인터페이스 하나 뒤에 둔다. SDK 타입은 `vehicle/` 밖으로 나가지 않는다.
- 구현: `RealVehicleSource`(Pleos + AAOS), `FakeVehicleSource`(JSON 시나리오 재생).
- 교체는 **빌드 종류(`real`/`demo`)로만** 한다. 실행 중 전환 메뉴는 없다(실제 기록에 가짜 값 섞임 방지).
- 운행 상태 머신은 Android를 모르는 순수 Kotlin으로 두어 Fake 신호로 전부 테스트한다.

## 결과
- 에뮬레이터에서 AAOS 신호가 안 읽혀도 `demo` 빌드로 시연·개발을 계속할 수 있다.
- **위험(높음)**: 실차에서 AAOS 신호를 못 읽으면 대체 신호(서비스 시작·종료 = 시동, 계기판 20초 정지 = P단, 가정)를 써야 하고 정확도가 떨어진다. 주행 중 입력 차단의 근거도 약해진다. → 첫 주 에뮬레이터 스파이크로 확인하고, 결과를 이 ADR에 덧붙인다.
- Pleos 값이 콜백 없이 조회만 되면 1초 주기 조회(가정)를 쓴다 — 배터리·성능 영향 확인 필요.
